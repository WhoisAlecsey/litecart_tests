# LiteCart — UI-автотесты

Автотесты интернет-магазина [litecart.stqa.ru](http://litecart.stqa.ru) на **Playwright + TypeScript**.

## Тест-кейсы

| Кейс                                 | Файл                                                 | Что проверяет                                                                  |
| ------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------ |
| TC1 — Заказ одного товара без скидки | [tests/order.spec.ts](tests/order.spec.ts)           | логин, 3 шт. товара без скидки, количество и цена в корзине, оформление заказа |
| TC2 — Заказ одного товара со скидкой | [tests/order.spec.ts](tests/order.spec.ts)           | то же для 2 шт. товара со скидкой, цена с учётом скидки                        |
| TC3 — Заказ товара без логина        | [tests/guest-cart.spec.ts](tests/guest-cart.spec.ts) | два товара в корзине, сумма, пустые данные покупателя, блок «Recently Viewed»  |
| TC4 — Невалидный логин               | [tests/login.spec.ts](tests/login.spec.ts)           | логин отклонён, сообщение об ошибке выделено красным                           |

TC1 и TC2 — один сценарий с разными данными, поэтому это один параметризованный тест.

## Запуск

Нужен Node.js 20+.

```bash
npm install
npx playwright install chromium
cp .env.example .env   # вписать учётки: CUSTOMER_* и REJECTED_*
npm test
```

| Команда                             | Действие                              |
| ----------------------------------- | ------------------------------------- |
| `npm test`                          | все тесты, headless                   |
| `npm run test:headed`               | с окном браузера                      |
| `npm run test:ui`                   | UI-режим Playwright                   |
| `npx playwright test -g "TC3"`      | один кейс                             |
| `npx playwright test --grep @order` | по тегу (`@order`, `@guest`, `@auth`) |
| `npm run report`                    | HTML-отчёт Playwright                 |
| `npm run allure:serve`              | отчёт Allure (нужна Java)             |

## Настройки

Читаются из `.env` (в git не попадает, образец — [.env.example](.env.example)).

| Переменная                            | Назначение                                                  |
| ------------------------------------- | ----------------------------------------------------------- |
| `BASE_URL`                            | адрес магазина, по умолчанию `http://litecart.stqa.ru`      |
| `CUSTOMER_EMAIL`, `CUSTOMER_PASSWORD` | зарегистрированный покупатель для TC1 и TC2                 |
| `REJECTED_EMAIL`, `REJECTED_PASSWORD` | пара e-mail / пароль, которую магазин не принимает, для TC4 |

Учётка из задания магазином не принимается, она используется в TC4 как невалидная (`REJECTED_*`).

## Структура

```
├── playwright.config.ts      конфигурация запуска и отчётов
├── tests/                    спецификации: только шаги кейса и проверки
└── src/
    ├── config/env.ts         единственное место, где читается process.env
    ├── fixtures/             выдача тестам готовых page object'ов и данных
    ├── pages/                страницы: Home, Product, Checkout, OrderSuccess
    ├── components/           блоки страниц: форма логина, корзина в шапке, список товаров, таблица заказа…
    ├── models/               предметная область: Money, Product, OrderLine, Color, Credentials
    └── data/                 тестовые данные: пользователи, фильтры товаров, тексты сообщений
```

Слои зависят только «вниз»: `tests → fixtures → pages → components → models`.

## Особенности стенда

- У https-версии просрочен сертификат и она отвечает в несколько раз медленнее, поэтому по умолчанию тесты идут по http. Для https достаточно поменять `BASE_URL`: в конфиге включён `ignoreHTTPSErrors`.
- Стенд общий и нестабильный: отдельные запросы зависают на 20–30 секунд. Поэтому увеличены таймауты, включены два повтора упавшего теста, страница считается открытой по `domcontentloaded` (без ожидания картинок), а зависшее открытие страницы повторяется (`BasePage.navigate`).
- Товары и цены на стенде меняются, поэтому тесты не привязаны к конкретному товару: он выбирается на главной странице по признаку (со скидкой / без скидки), а ожидаемая сумма считается из цены, показанной на странице товара.
- Магазин хранит корзину покупателя между сессиями, поэтому в TC1 и TC2 корзина очищается после логина.
- Порядок строк в корзине не совпадает с порядком добавления, поэтому в TC3 строки сравниваются без учёта порядка.
- TC1 и TC2 создают в магазине реальные заказы от имени тестового покупателя.
